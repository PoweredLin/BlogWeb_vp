# 邮件推送故障排查

## 先确认加密密钥

SMTP 授权码不会明文写入数据库。服务端必须先设置 `EMAIL_ENCRYPTION_KEY`，否则保存邮件设置会返回 `尚未配置 EMAIL_ENCRYPTION_KEY`，测试邮件不会开始发送。

宝塔 Docker 部署时，密钥写在项目目录 `.env`，与 `compose.yaml` 同级；不要写进 `.env.example` 或 `public/`。在可信设备上生成一次：

```sh
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

把输出整行填入 `.env`：

```dotenv
EMAIL_ENCRYPTION_KEY=生成的完整密钥
```

妥善保存这个密钥并保持长期不变。若密钥丢失或更换，数据库里已保存的授权码无法解密，需要重新录入；不要删除或覆盖线上数据库。

修改 `.env` 后强制重建服务容器，使新环境变量生效：

```sh
cd /www/wwwroot/lin-notebook-v10
docker compose up -d --force-recreate space
docker compose ps
docker compose logs --tail=50 space
```

可以安全地只检查容器是否读到密钥，不会输出密钥内容：

```sh
docker compose exec space python -c "import os; print('EMAIL_ENCRYPTION_KEY 已设置' if os.getenv('EMAIL_ENCRYPTION_KEY') else 'EMAIL_ENCRYPTION_KEY 未设置')"
```

## 核对 SMTP 配置

管理页的 SMTP 主机、用户名、发件邮箱、收件邮箱和端口应按邮箱服务商的 SMTP 页面填写。用户名一般是完整邮箱地址；密码应使用服务商的 SMTP 授权码或应用密码，不一定是邮箱网页登录密码。

| 端口 | 管理页加密方式 | 常见用途 |
| --- | --- | --- |
| `587` | `STARTTLS` | 常见的提交端口 |
| `465` | `隐式 TLS` | 服务商提供 SSL/TLS 连接时使用 |

不要将 465 与 STARTTLS、或 587 与隐式 TLS 混搭。优先使用服务商明确提供的主机名、端口和加密方式。

## 按错误提示排查

| 页面提示 | 检查项 |
| --- | --- |
| 尚未配置 `EMAIL_ENCRYPTION_KEY` | 按上文在服务器 `.env` 设置密钥，然后强制重建容器 |
| SMTP 登录被拒绝 | 用户名、应用授权码、账号 SMTP 开关和登录限制 |
| TLS 握手失败 | 465/隐式 TLS 与 587/STARTTLS 是否匹配 |
| 无法解析 SMTP 服务器地址 | SMTP 主机名拼写、服务器 DNS |
| 连接超时或无法连接 | 主机/端口、防火墙、云厂商出站 SMTP 端口策略；不要默认使用 25 端口 |
| 发件地址被拒绝 | 发件邮箱应符合该 SMTP 账号及服务商的发件人策略 |
| 测试邮件结果未知 | 先查收件箱和垃圾邮件；确认没有收到后再重试，避免重复发送 |

“发送测试邮件”会先保存当前表单，再使用一次 SMTP 会话投递到测试收件箱。成功提示后也请检查垃圾邮件。测试接口和服务器日志不会回显授权码或 SMTP 服务商的原始响应文本。

真实投递取决于邮箱服务商授权、发信额度、服务器 DNS 和云厂商网络策略。单元测试使用模拟 SMTP，不代表公网发信链路已验证。不要把 `.env`、邮箱密码或授权码贴进聊天、截图或 Git 提交。

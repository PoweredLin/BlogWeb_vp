# 在 2 核 4 GB 上做个人网站：把工作放在合适的位置

个人网站通常不缺功能想法，缺的是明确的资源预算。林间笔记使用单实例 FastAPI 与 SQLite，Docker 限制进程内存及 CPU。这样的组合适合个人内容管理；浏览器爬虫、大模型推理和高并发批处理则应另找执行环境。

## 页面只拿当前需要的数据

首页 bootstrap 返回站点、导航、片头和少量文章元数据；模块接口按配置返回当前需要的内容。文章和番剧目录支持分页，默认不传正文或私人笔记。分页响应统一为 `items,total,page,pageSize,hasMore`，page 从 1 开始，pageSize 最大 100。

文章元数据通过 SQLite JSON 投影读取，不将全部文章正文反序列化到 Python。番剧按季度和搜索条件过滤；星期来自来源站的播出描述，没有信息就保留为待定，不伪装成实时更新日历。

## 长任务与页面轮询

自动化的列表轮询使用 compact 摘要，避免每次重复传回完整采集正文。只有选中某次运行、或该运行的状态发生变化时才请求完整详情。任务创建、编辑、删除与结果确认使用现有版本保护，409 表示应重新读取并处理并发变动。

复杂资料整理可在本机执行，云端承担鉴权、接收、去重、保存和审核。新闻摘要、季度番剧整理、每周日志都可以使用这个模式。云端不执行用户任意脚本，也不提供任意 URL 的通用抓取代理。

## SQLite 的适用边界

单站主、有限读者和轻量任务目前不需要额外数据库服务。备份必须覆盖数据库、上传图片和必要配置；运行中的数据库不能仅用随意复制主文件替代一致性备份。多实例写入、任务量持续增长或索引不足时，再测量慢查询并考虑迁移。

现有素材库仍扫描文件及引用，海量素材时应增加索引。按星期筛选仍需解析有限的番剧元数据。这些是明确的后续优化点，不能仅凭接口分页就宣称所有查询都有固定成本。

## 状态检查也需要预算

侧栏和页脚共用状态模块，同一页面只保留一个每分钟定时器。标签页隐藏时不主动查询；请求超时后给出无法确认状态，而不是一直显示绿色。这个检查证明应用和数据库此刻可用，不代表 SMTP、第三方文档或来源站也可用。

对应源码：`backend/experience.py`、`backend/automation.py`、`source/blog/src/integration/site-status.js`。上线观察真实响应耗时、内存、错误与外站限流，再决定是否增加缓存或队列。

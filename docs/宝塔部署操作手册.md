# BlogWeb_vp 宝塔部署操作手册

适用场景：你的博客已经在线运行，服务器为 2 核 4G，域名为 `lolicong.xyz`。本次将现有 V9 升级到 V10，继续使用 Vue 3 + FastAPI 和 Docker。旧目录、旧容器及旧数据保留用于回滚。

推荐顺序：**准备代码和镜像 → 停止旧服务 → 备份并复制线上数据 → 启动新版 → 验证网站。** 下载和构建应在停旧站之前完成，缩短停机时间。

仓库：<https://github.com/PoweredLin/BlogWeb_vp>，分支 `main`。`_vp` 是仓库名称后缀；当前应用版本仍为 V10，镜像名仍是 `lin-notebook:10`，不用手动改 Compose 中的镜像名。

## 一、分清本地与服务器

| 位置 | 用途 |
| --- | --- |
| 本机项目目录 | 修改源码、测试、构建镜像 |
| 本机 `lin-notebook-v10.tar` | 已导出的运行镜像，约 193MiB；不含线上文章图片 |
| 服务器旧目录 | 当前程序与真实数据，需要保留以便回滚 |
| 服务器新目录 `/www/wwwroot/lin-notebook-v10` | 存放新部署配置和迁移后的数据 |
| 新目录 `data/space.sqlite` | 迁移来的数据库 |
| 新目录 `data/uploads/` | 迁移来的图片 |
| 新目录 `.env` | 域名和可选服务端配置 |

下面标明“服务器”的命令在宝塔终端或 SSH 中执行；不要将 Windows 路径粘贴到服务器。所有示例旧路径都必须与实际旧服务的数据挂载一致。

## 二、准备 Docker 和代码（服务器）

在宝塔 Docker 管理中安装/启用 Docker，或者按 Docker 官方方式安装 Docker Engine 和 Compose 插件。确认：

```sh
docker --version
docker compose version
docker info
```

三条命令均正常后，创建新版目录。以下命令仅在新目录尚不存在时执行：

```sh
cd /www/wwwroot
git clone --branch main https://github.com/PoweredLin/BlogWeb_vp.git lin-notebook-v10
cd lin-notebook-v10
```

若服务器无法连接 GitHub：在本机下载 GitHub 源码 ZIP，通过宝塔上传并解压。解压后的 `compose.yaml` 应直接位于 `/www/wwwroot/lin-notebook-v10/`，不要多套一层文件夹。也可仅上传同一版本的 `compose.yaml`、`.env.example` 和镜像 TAR，按下一节使用 `--no-build` 运行；这种精简上传方式不能在服务器构建源码。

不要上传本机的 `data`、`.env`、`node_modules`、`.venv` 或整个历史备份目录。

## 三、准备运行镜像

### 推荐：上传本机镜像（服务器）

本机项目根目录已有 `lin-notebook-v10.tar`。将它上传到服务器新目录；它是 Docker 镜像包，不是站点源码压缩包，不要在宝塔中解压。

```sh
cd /www/wwwroot/lin-notebook-v10
docker load -i lin-notebook-v10.tar
docker image inspect lin-notebook:10 --format '{{.Os}}/{{.Architecture}}'
uname -m
```

目前本机构建的镜像用于 Linux amd64；服务器 `x86_64` 对应 amd64。若服务器是 ARM/aarch64，需要为目标架构重新构建，不能直接套用。

当前 TAR 是导出时的代码快照。以后修改源码不会自动更新这个文件；需要在本机重新导出：

```powershell
docker compose build
docker save -o lin-notebook-v10.tar lin-notebook:10
```

然后重新上传并 `docker load`。不要同时在服务器执行构建来覆盖刚加载的目标镜像。

### 可选：在服务器构建

只有上传了完整源码、网络和内存允许时才选择：

```sh
cd /www/wwwroot/lin-notebook-v10
docker compose build
```

Python 官方源下载慢时：

```sh
docker compose build --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
```

构建成功后再停旧站；构建失败时旧站可继续运行。

## 四、设置 .env（服务器）

在新目录复制模板。已有 `.env` 时不要覆盖，应直接检查编辑：

```sh
cd /www/wwwroot/lin-notebook-v10
cp -n .env.example .env
chmod 600 .env
```

使用宝塔文件编辑器编辑 `.env`，关键内容如下：

```dotenv
APP_ENV=production
SITE_URL=https://lolicong.xyz
COOKIE_SECURE=true
FORWARDED_ALLOW_IPS=172.30.17.1
```

`SITE_URL` 不加末尾 `/`，必须与浏览器实际地址一致。`GITHUB_TOKEN` 可不填，Git 日历仍可尝试读取公开动态；它与代码仓库登录不是一回事。

当前 Compose 固定容器监听 `0.0.0.0:4317`，对宿主机只发布 `127.0.0.1:4317`。模板中的 `HOST`、`PORT` 不会修改 Compose 的端口映射；`DATA_DIR` 注释也不会修改 Compose 的 `./data:/app/data` 挂载。

检查配置：

```sh
docker compose config --quiet
```

Compose 默认项目名是 `lin-notebook`。如果旧版也是同项目名的 Compose 部署，在新 `compose.yaml` 顶部将 `name: lin-notebook` 改成 `name: lin-notebook-v10`，避免新版管理命令操作到旧项目。旧版的启动方式和项目名要先记下来。

如果提示网络地址池重叠，检查其他 Docker 网络；同时调整 Compose 中的 `172.30.17.0/24` 和 `.env` 中对应网关。不要使用 `FORWARDED_ALLOW_IPS=*`。

## 五、停旧站并迁移真实数据（服务器）

先在宝塔确认旧网站是 Node 项目、PM2 进程还是 Docker 容器，并记录启动方式、目录和数据挂载。只停止实际运行的那一个服务。不要猜进程名批量停止其他网站。

查看 4317 是否已释放：

```sh
ss -ltnp 'sport = :4317'
```

若仍有监听，先确认占用者。不要用强杀命令盲目清端口。

### 旧数据是主机目录

假设已确认真实数据位于 `/www/wwwroot/lin-notebook/data`，旧服务已经停止，并且新目录尚无 `data`：

```sh
cd /www/wwwroot/lin-notebook-v10
ls -lah /www/wwwroot/lin-notebook/data
test -f /www/wwwroot/lin-notebook/data/space.sqlite && test -d /www/wwwroot/lin-notebook/data/uploads && test ! -e ./data && cp -a /www/wwwroot/lin-notebook/data ./data
```

这一条带检查的复制命令只在源文件存在且目标不存在时执行。若检查未通过，先核实路径，不要绕过检查直接覆盖。复制后确认：

```sh
ls -lah data/space.sqlite
ls -lah data/uploads
mkdir -p backups
test ! -e backups/pre-v10-production-data && cp -a data backups/pre-v10-production-data
chown -R 10001:10001 data backups
chmod 700 data backups
```

以 root 执行上述权限命令，普通账号需加 `sudo`。备份目录已存在时不要重复覆盖。把备份另存到本机或其他存储；同一服务器的副本不能应对整机丢失。

要复制整个停机后的 `data`，包括可能存在的 SQLite `-wal`/`-shm` 文件。不要只拷正在写入的 `space.sqlite`。

### 旧数据在 Docker 卷里

先查看实际旧容器挂载（替换容器名称）：

```sh
docker inspect <旧容器名称> --format '{{json .Mounts}}'
```

确认容器已停止、旧应用数据确实在 `/app/data`，且新目录还没有 `data` 后：

```sh
docker cp <旧容器名称>:/app/data ./data
```

然后执行上一小节的备份和目录权限步骤。不要执行 `docker compose down -v`，也不要删除旧容器或旧数据卷。

**你的站点已有账号、文章和图片：跳过 owner-init，不能重新初始化，更不能复制本机测试数据过来。**

## 六、启动新版（服务器）

```sh
cd /www/wwwroot/lin-notebook-v10
docker compose up -d --no-build
docker compose ps
docker compose logs --tail=100 space
curl -fsS http://127.0.0.1:4317/healthz
curl -fsS http://127.0.0.1:4317/api/status
```

预期：

- `healthz` 返回 `{"ok":true,"version":"10.0.0"}`。
- 已有账号时 `setup:false`；未登录时 `authenticated:false` 是正常的。
- 容器健康状态开始可能是 `starting`，稍后应变为 `healthy`。

若 `setup:true`，先停止新版并检查数据挂载；不要以为这是要求重新创建账号。首次迁移会自动保留 `data/migration-safety/before-v10.sqlite`，但它不是包含全部图片的全站备份。

## 七、宝塔 HTTPS 与反向代理

在宝塔的网站管理中找到 `lolicong.xyz`，确认 SSL 证书有效、启用 HTTPS。反向代理目标为 `http://127.0.0.1:4317`。

若旧站本来就代理到该地址，通常保留即可，但仍需检查下面的请求头、上传大小和旧静态首页规则。

在该域名对应的 HTTPS `server` 中配置：

```nginx
client_max_body_size 12m;
client_body_timeout 30s;

location / {
    proxy_pass http://127.0.0.1:4317;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 5s;
    proxy_read_timeout 60s;
    proxy_send_timeout 60s;
}
```

已有 `location /` 时编辑原规则，不再添加第二条。宝塔自动生成的代理配置有时在 include 文件中，先检查再改。不要让原测试 `index.html` 或 `try_files ... /index.html` 接管首页，也不要将项目源码根目录直接作为静态站点对外开放。

宝塔执行配置检查，通过后重载 Nginx。公网安全组无需开放 4317。用 `https://lolicong.xyz` 登录，不能用普通 HTTP 验证生产 Secure Cookie 登录。

## 八、上线验收

1. 无痕窗口访问首页、原来的两篇文章，逐一打开图片。
2. 登录原站主账号，检查文章、相册、说说、私人记录和设置。
3. 新建草稿并保存，确认无痕窗口看不到草稿。
4. 提交测试评论，审核前不公开，审核后才出现。
5. 读者账号不能进入创作管理和私人工作台。
6. 切换两种空间主题、预览背景，检查移动端布局。
7. Git 动态可能先显示后台同步；稍后刷新，不应拖慢其他功能。
8. 执行 `docker compose restart space`，再次确认文章与图片仍存在。

## 九、日常管理与备份（服务器）

均在新部署目录执行：

```sh
docker compose ps
docker compose logs --tail=100 space
docker compose restart space
docker stats --no-stream
```

做全站备份时先暂停写入，选择一个没有使用过的备份目录名：

```sh
docker compose stop space
docker compose run --rm space python -m backend.cli backup --destination /app/backups/full-2026-10-26-01
docker compose start space
```

确认输出 `Full backup complete`，并检查对应备份里有 `space.sqlite` 和 `uploads`。失败时保留错误输出，恢复服务后排查，不要删除原数据。把备份复制到服务器之外。

界面里的 JSON 导出不是完整站点备份。忘记密码可执行：

```sh
docker compose run --rm space python -m backend.cli owner-reset
```

输入两次至少 10 字符的新密码；已有内容不会删除，旧站主会话会撤销。

## 十、升级失败时回滚

如果切换后还没有新增内容：停止新版 `docker compose stop space`，用之前记录的方式启动旧服务，让它继续使用未被新版写入的旧目录或旧卷。如果反向代理目标未改，旧服务恢复 4317 后即可重新验证网站。

如果新版已新增文章、评论或上传图片：先备份新版完整数据，不要直接用旧备份覆盖。需要明确哪些新内容要迁回，再决定恢复方案。

不要让两个版本同时写同一数据库。保留旧程序、旧配置、旧数据及迁移前备份，直到新版验收完成。

## 十一、问题定位速查

| 现象 | 先检查什么 |
| --- | --- |
| 502 / Connection refused | `docker compose ps`、日志、4317 监听、代理目标 |
| 容器反复重启 | 日志中的数据权限、SITE_URL、数据库错误 |
| address already in use | 旧进程是否仍占用 4317 |
| setup:true | 是否挂载了真正的线上 data，是否出现 data/data |
| 登录 403 | HTTPS 域名与 SITE_URL 是否一致、Host/Origin 是否正确 |
| 登录后马上退出 | Secure Cookie、HTTPS、系统时间、是否切到了不同实例 |
| 上传 413 | Nginx 请求上限；单图不得超过 8MiB，JSON 请求上限 12MiB |
| 图片 404 | uploads 是否完整、图片是否已被公开内容引用 |
| 仍显示旧测试首页 | Nginx 命中的站点、旧静态规则、代理缓存、浏览器缓存 |
| Git 不更新 | 用户名与平台、后台刷新及缓存冷却、平台限流 |
| 内存偏高 | `docker stats --no-stream`，不要在 2 核 4G 上同时构建多个项目 |

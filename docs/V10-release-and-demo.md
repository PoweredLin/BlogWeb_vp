# V10 本地演示与部署升级说明

## 本地演示

V10 使用 Vue 3、FastAPI 与 SQLite。Node.js 仅用于前端依赖和构建；运行网站服务时由 Python 启动。演示数据固定写入 `data/demo-v10`，与默认的 `data/space.sqlite`、上传目录和线上站点分开。演示启动器拒绝把演示程序指向其他数据目录。

在项目根目录运行：

```powershell
npm run demo
```

默认浏览器打开 <http://127.0.0.1:4321>；当前工作区演示使用 <http://127.0.0.1:4322>。管理员账号为 `admin`。首次创建演示库时会在终端生成随机密码；已有演示账号密码保持原值，不在 Git 中记录。忘记密码时可以仅重置演示库：

```powershell
npm run owner:reset -- --data-dir data/demo-v10
```

在提示中输入新密码。不要把 `--data-dir` 改为 `data` 或服务器的真实数据目录。第一次运行如未安装依赖，先按 README 的本地开发步骤安装 Python 与 npm 依赖；`npm run demo` 不会覆盖已有演示内容，重置账号也不会清除文章、图片或设置。

建议按这个顺序体验：

1. 从首页查看“林间笔记”的照片拼字开场；开场可跳过，之后进入轮播首页。首次访问、刷新和深链均应能正常进入内容页。
2. 登录 `/admin/room` 查看私宅工作台，再到 `/admin/management` 使用简约管理台；文章、说说、相册和任务等入口分开管理。
3. 在管理台查看页面布局、个人空间主题、背景和头像设置；保存公开布局前可先检查桌面与手机预览。
4. 在“自动化”打开“本季度新番 · 手动预览”，运行后查看来源、封面和预览；演示数据库保留了两条已验证的示例结果。新抓取内容先进入个人收藏/文档，由站主审核后保存。
5. 在“开发书架”打开内嵌文档，在私人文档中查看 Mermaid 流程图。
6. 在“AI 接入”创建最小权限 Access Token，并用 JSON 校验/导入或 `scripts/local-ai-submit.py` 提交草稿。令牌只在创建时展示；不要把真实令牌放入仓库或聊天记录。
7. 邮件设置可以检查表单和预览。SMTP 投递需配置稳定的 `EMAIL_ENCRYPTION_KEY` 及邮箱服务商的授权码；当前演示没有真实邮箱凭据，因此不能用演示站确认真实邮件投递。

## 已交付范围与边界

- 个性化工作台与简约管理台共用一套权限和数据，不提供面向客户的通用低代码编辑器；个人可编辑首页模块和外观，业务功能随版本更新。
- 首页照片拼字片头支持跳过、结束转场和减少动态效果回退；非首页深链不应被片头拦截。
- Access Token 采用 scope、期限、撤销、只存摘要和幂等键；默认创建草稿。JSON 导入先校验后写入，流程和邮件均不交给任意 AI 输入控制。
- 新番收集是固定来源、限量抓取、封面校验、去重和人工预览的轻量流程；不运行任意插件代码，也不承诺绕过来源站限制。
- 计划邮件与手动邮件都有明确状态与重试边界。SMTP 已通过模拟器测试，尚未用真实收件箱验证。
- 外部开发文档使用白名单来源和 iframe 策略；浏览器阻止嵌入时可打开原站。

## V10 部署前检查

线上升级按 [V10 线上升级与回滚步骤](V10-upgrade-and-rollback.md) 操作。不要把本地 `data/demo-v10`、演示图片、`.env` 或测试结果复制到服务器。生产数据只能从服务器自身的停写备份恢复。

发版前应完成：

```sh
npm ci
npm test
npm run build
npm run test:browser
npm run test:appearance
npm audit --registry=https://registry.npmjs.org
python -m pip_audit -r backend/requirements.lock.txt
```

容器构建另按部署机执行 `docker compose build` 和隔离容器测试。没有 Docker 引擎时不能把本地 Docker 验证标记为通过。部署前另需用服务器数据库副本预演迁移，并用实际邮箱与测试收件箱验证 SMTP；两者都不能由演示站的模拟测试代替。

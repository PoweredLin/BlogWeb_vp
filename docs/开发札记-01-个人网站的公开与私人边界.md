# 从博客到个人空间：公开与私人边界怎么划分

林间笔记有两种使用场景：访客阅读，以及站主创作和收藏。两者共享一套数据库，却不应该共享一份完整响应。这是网站从静态页面发展到个人应用后最需要先整理的部分。

## 内容由谁控制

文章、说说、相册与任务管理属于站主。读者注册需要验证码及审核，注册后只能维护自己的资料和参与评论。评论仍需站主审核。前端隐藏按钮只能改善操作体验，真正的权限判断必须在服务器完成，直接请求私人接口同样会被拒绝。

公共入口使用 `/api/public/bootstrap`、`/api/public/home` 和分页目录接口。它们从数据库提取公开字段，而不是先向浏览器发送私人空间，再用 JavaScript 删去不该展示的部分。文章卡片不需要全文；番剧海报不需要私人笔记、进度或任务凭证。

## 图片的公开由引用决定

上传文件并不天然公开。`/uploads/{name}` 会检查图片归属及其是否被公开内容引用，站主可访问自己的草稿素材，匿名访问者只能读取已经公开引用的图片。把某张图加入公开片头并保存，就意味着允许这张图公开显示。

素材查询、预览和发布是不同的动作。`/api/private/media` 返回可供选择的素材，不会因为查询操作而改变文件的公开范围。任意新增的前端主题也要沿用这些 URL 和权限规则，不能直接把私人素材复制到公开静态目录。

## 自动化先进入收件箱

云端轻量采集和本地 AI 提交都应先产生可检查的结果，站主确认后再保存到文档、收藏或邮件。已确认采集的番剧可以通过总开关公开元数据；手动私人收藏使用单独公开开关。总开关不应把收藏笔记一起公开。

本地 AI 使用有作用域的 Access Token，接口为 `/api/v1/automation/results`。Token 不存入公共前端，幂等键通过 `Idempotency-Key` 请求头传递；重复提交相同结果不会重复创建，键相同而内容不同则报告冲突。

## 可继续改进的地方

后续增加新展示模块时，先写清楚字段的公开范围、所属用户、审核状态和图片引用，再写组件。API 契约页和权限测试是改版的基础。页面看起来不同，可以共用同一套经过验证的业务边界。

对应源码：`backend/main.py`、`backend/security.py`、`backend/content.py`、`backend/experience.py`。阅读接口说明见 [API 基础](API-frontend-foundation.md)。
